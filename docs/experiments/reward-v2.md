# 보상 재설계와 행동 고정 진단

사용자 요청: 전진·적 처치·사망을 고려해 보상 체계를 재설계하고 새로 학습한다. 업데이트 수가 증가하는 것과 게임 실력 향상을 구분한다. 기존 Run은 수정하지 않는다.

## 관찰과 가설

`reports/t16-acceptance-004/collapse-diagnosis.json`의 최근 5,711개 실제 전이는 모두 행동4(`RIGHT+B+A`)였고 사망155회를 포함했다. 해당 표본에서 최대 행동 확률은0.9999987 이상이다. 초기 평가 평균518.33px에서 후속273px로 하락했다. 이는 화면 표시만의 문제가 아니다.

원인 후보는 (1) 전진 대비 작은 사망 비용, (2) 32전이 단위의 짧고 상관된 경험, (3) 탐색 소실이다. 원인별 인과를 확정한 실험은 아니다. 새 실행은 여러 설정을 함께 변경하므로 성과가 달라져도 특정 한 변경의 효과로 단정하지 않는다.

## 첫 후보

| 사건 | 보상 | 의도 |
|---|---:|---|
| 새 최대 전진 거리 | +0.01/px | 왕복으로 같은 구간의 보상을 재수령하지 않음 |
| 활성 게임 시간 | −0.001/frame | 빠른 진행 선호; action repeat 크기와 독립 |
| 60프레임 초과 정체 | −0.005/frame 추가 | 점프 준비·짧은 회피는 허용 |
| 사망·게임 시간 초과 | −10 | 기존 대비 전진 보상과의 비율100배 강화 |
| 300프레임 정체 | −10, terminal | 가만히 기다리는 안전한 탈출 방지; bootstrap하지 않음 |
| 완주 | +100 | 가장 큰 성공 목표 |
| 확인된 적 처치 | +0.5, 에피소드당 합계 최대5 | 부차 목표; 코인/점수 증가로 대체하지 않음 |

사망 감점은 새 전진1,000px에 해당한다. 이것은 검증된 최적값이 아니라 실험 후보다. 외부 평가/학습 프레임 제한은 truncation으로 유지하고 사망으로 계산하지 않는다. 입력은 화면 픽셀뿐이며 RAM 이벤트는 보상과 보고서에만 사용한다.

적 처치는 활성 enemy slot의 동일 ID에서 defeated bit5가 새로 켜지거나 Goomba가 stomped state4로 전환되는 사건으로 제한한다. 같은 개체의 상태가 흔들려도 slot이 비활성화되거나 ID가 바뀌기 전에는 다시 보상하지 않는다. Koopa가 껍질로 들어가는 것은 영구 처치로 계산하지 않는다. 지원 ROM World1-1 범위의 검증이며 일반 게임 이벤트 검출기는 아니다.

학습 후보는 rollout128, epochs2, learning rate0.0001, gamma0.995, GAE lambda0.97, clip0.1, entropy coefficient0.05이다. 고정된 행동의 기존 가중치를 재사용하지 않고 새 seed7 초기 정책에서 시작한다. 행동 자체의 의미나 버튼 매핑은 바꾸지 않는다. 숫자는 `configs/game-reward-v2.json`, `configs/training-reward-v2.json`에 저장한다.

## 검증 기준

환경 경계에서 전진/왕복/사망/정체/적 처치의 보상 항목 합계를 검사한다. 실제 NES 녹화 행동 재생으로 적 상태 이벤트를 검증한다. CLI에서 항목별 누적값과 행동 빈도, 저장 후 재개의 누적 연속성을 확인한다.

새 Run 안에서 초기/주기 평가에 동일 프로토콜(3 seeds, 최대1800게임프레임)을 적용한다. 총보상을 구형 Run과 직접 비교하지 않는다. 이동 거리·완주·사망/정체·행동 분포를 보고하며, 짧은 실험의 개선이나 실패를 일반화하지 않는다. 평가·게임 플레이 압축 영상과 회로 관찰 기록을 보존한다.

## 근거

- [PPO 공식 설명](https://spinningup.openai.com/en/latest/algorithms/ppo.html): 확률 정책의 탐색은 학습 중 줄어들 수 있고 지역 최적점에 갇힐 수 있다. clipping만으로 큰 정책 변화를 완전히 막지는 않는다.
- [SMB 역어셈블 원문](https://github.com/pgattic/smb1-disasm/blob/master/main.asm): `ShellOrBlockDefeat`, `EnemyStompedPts`, `HandleStompedShellE`의 상태 전환. RAM 주소는 같은 저장소의 `constants/constants.asm`에 정의되어 있다. 실제 지원 ROM에서 별도로 검증한다.

사용자 후속 요청에 따라 새 학습은 우선10분 세션으로 제한한다. 초기 평가와 준비 후 학습을 시작하고,10분 뒤 안전 저장·종료한 최종 정책을 같은 평가 프로토콜로 검사한다. 업데이트 예산100000은 자동 종료 한도가 아니라 상한이며, 실험 도구가 시간 제한을 제어한다. #17의 완료된1시간 안정성 검사와 학습 성과 실험을 혼동하지 않는다.

## 실행과 검증

```bash
uv run --offline --locked --extra graph --extra train python scripts/reward_trial.py \
  --output reports/my-reward-trial --seconds 600 --queue-thread "$CODEX_THREAD_ID"
```

초기 정책 평가와1 update 준비를 마친 뒤 새 프로세스에서600초 세션을 실행한다. 초기 평가 시간은 제외하고, 재개 준비·주기 평가·마지막 안전 저장 시간은 세션 벽시계에 포함된다. `summary.json`은 벽시계 시간과 실제 학습 시간을 구분한다. `ready.json`, `trainer.log`, `summary.json`, `queue-delivery.json`을 남긴다. 같은 출력 Run 덮어쓰기는 거부한다. 큐 옵션을 생략하면 후속 메시지 없이 종료한다. 큐 전송은 실패 시에도 시도하며, 환경이 강제로 종료되는 상황까지 보장하지는 않는다.

합성 환경·CLI 경계9개 및 실제 NES4개 검사를 통과했다. 이후 누락 이벤트/잘못된 비용 거부와 기존 Run 덮어쓰기 거부를 추가 검증했다. mypy38개 소스 통과. 전체 회귀112개를 모두 통과했다(49/39/24개 세 묶음, 전체 벽시계323.04초). 10분 성과는 아래에 기록했다.

Standards 리뷰: 명시 규칙 위반0, heuristic0. Spec 리뷰: 저장·종료 실패 시 큐 전송 누락1건을 수정했고 재검토 남은 지적0. 리뷰 통과가 실제 학습 성과를 보장하지 않는다.

실제 새 실행: `reports/reward-v2-001/run`. 초기 평가와 첫 업데이트 후10분 세션을 시작했다. 고정 관전 주소는 `http://localhost:8766`이며 viewer는 학습 종료 후에도 유지한다. Windows PowerShell HTTP200, WSL Chromium 게임 화면·회로·입력·행동 분포 표시를 확인했다. 실제 Windows 화면 수동 성공 확인을 뜻하지 않는다.

시작 직후57 updates에서7개 행동 모두 선택됐고 직전 rollout entropy는1.633이었다. 이는 초기 탐색이 동작한다는 증거이며 성과 개선의 근거는 아니다. 종료 후 `reports/reward-v2-001/analyze.py`로 초기/최종 평가와 누적 보상·행동 진단을 정리한다. 기존1시간 완료 큐의 분석·오프라인 복원·#17 갱신은 이미 처리했으므로 같은 Run을 다시 재개하지 않는다.

최종 평균 거리는 초기 대비411.67px(+83.05%) 증가했다. 세 seed 모두 초기보다 멀리 갔지만, 완주나 생존 개선은 확인되지 않았다. 중간 평가에서는555px 부근에 정체했다가 마지막 평가에서 더 멀리 진행했다. 3회 평가만으로 안정적인 개선·일반화를 확정하지 않는다.

학습 전체 행동0~6 선택 횟수는9,498 /14,834 /8,021 /6,135 /20,615 /12,574 /6,787이었다. 마지막128회는5 /13 /3 /3 /90 /7 /7: 행동4가70.31%로 여전히 편중됐다. 같은 구간 행동4의 평균 확률은63.77%, entropy는1.287nats이다. 구형 Run의 최근5,711회 전부 행동4·거의0 entropy와 비교하면 완전 고정은 해소됐으나, 이는 새 초기화와 여러 설정을 동시에 바꾼 결과다. 보상 변경 하나만의 효과로 해석하지 않는다.

누적 보상은 전진+2700.10, 적 처치+179.00(358회 감지), 사망−2580, 정체 종료−1890, 정체 시간−366.82, 활성 시간−312.781, 완주0이었다. 이 값은 학습447개 종료 에피소드(사망258·정체189)와 진행 중 에피소드를 합친 진단값이며, 평가 결과나 구형 총보상과 직접 비교하지 않는다. 적 처치 능력이 향상됐다는 비교 근거는 아직 없다.

다음 개선 후보는555px 주변 정체와 최종 평가 사망 장면의 영상 분석, 상태에 따른 점프 버튼 해제·재입력 및 행동 확률 점검이다. 사망 감점만 다시 올리는 것으로 결론내리지 않는다. 사용자의10분 우선 확인 요청에 따라 이 결과에서 실행을 멈춘다. 실제 Windows 화면과 WSL/PC 재시작 확인은 여전히 별도 미완료다.
