실행일: 2026-10-10 (Asia/Seoul). 대상: GitHub #2, 부모 #1의 A1 / AC-01 / game-contract / environment-diagnostics.

## 게임 식별과 동작 증거

- 게임: `SuperMarioBros-Nes-v0`, 코어 `fceumm`, integration `flycade-smb-1`.
- 시작 state: `Level1-1`, SHA-256 `905a2e5d8a1bcc8b5955d132a77a8244025d205c2c6a9b07404758d3b84174b5`.
- 사용자 ROM 전체 SHA-256: `f61548fdf1670cffefcc4f0b7bdcdd9eaba0c226e3b74f8666071496988248de`.
- ROM payload SHA-1: `facee9c577a5262dbe33ac4930bb0b58c8c037f7` (16바이트 iNES 헤더 제외).
- 설치 릴리스에서 state 목록 및 버튼 순서를 조회했다. 런타임 버튼은 `[B, null, SELECT, START, UP, DOWN, LEFT, RIGHT, A]`이다.
- 실제 시작 화면에서 WORLD 1-1 / TIME 400을 확인했다. reset RAM은 world=0, level=0, engine=8, position=40, screen=0, lives=2였다.
- 실제 RGB 원본 해상도는 **240×224**(배열 224×240×3)이며 흔히 예상하는 NES 전체 래스터 크기를 하드코딩하지 않는다. 정책에는 4×84×84×3 uint8 픽셀만 전달했다.

| --- | --- | --- | --- |
| `a1-first` | 7개 행동 순환, x=40→584; 외부 예산 truncation | 480 | 120 |

`a1-first`의 실제 좌표 252→258, 510→516에서 page 순환을 처리했으며, 화면 스크롤이 471까지 증가해도 중복 진행 보상을 만들지 않았다. 437→436의 후퇴에는 진행 보상 0을 기록했다. 합성 테스트는 더 긴 왕복과 동일 최고점 재방문·reset 기준점 재설정을 별도로 검사한다.

완료 시퀀스는 RAM과 에뮬레이터 state 탐색으로 만든 **진단용 고정 입력**이다. 정책 학습이나 커넥톰 성능이 아니다. 탐색 상태를 가져오지 않고, 새로운 CLI 프로세스가 고정 1-1 state에서 [행동 목록](completion-actions.json)을 처음부터 재생하여 완료를 재확인했다. 깃발 아래로 내려온 실제 화면도 확인했다. 완료는 engine 5 진입으로 정의하며 성 입장 애니메이션 종료를 기다리지 않는다.

## 재현 명령

README의 설치/ROM 등록 이후, 기존에 없는 출력 디렉터리를 사용한다.

```bash
uv run --offline --locked flycade demo --output reports/recheck-actions --steps 120
uv run --offline --locked flycade demo --output reports/recheck-death --actions 1 --steps 300
uv run --offline --locked flycade demo --output reports/recheck-stall --actions 0 --steps 200
uv run --offline --locked flycade demo --output reports/recheck-timeout --actions 0 --steps 6000 --config docs/validation/timeout-config.json
uv run --offline --locked flycade demo --output reports/recheck-completion --steps 342 --actions-file docs/validation/completion-actions.json
```

동일 상태의 idle과 RIGHT 20전이를 별도 프로세스에서 비교하면 idle은 x=40을 유지하고 RIGHT는 전진한다. RIGHT를 다시 실행하면 마지막 관측 해시와 전이 결과가 일치한다. 단순히 버튼 mask를 기록한 것뿐 아니라 실제 반영을 검사한다.

## 자동 검증 경계

- CLI: 환경 보고, catalog, ROM 누락/해시 오류, 실제 등록/inspect/데모, 손상/누락 state 거부, 별도 프로세스 reset 재현, 완료 행동 파일 재생.
- 공개 `GameEnv.reset/step`: 합성 RGB 입력으로 action repeat, 버튼 mask, 픽셀 누적/회색조, byte 경계와 왕복 보상, 사망/완료/시간 만료와 외부 truncation, 종료 후 reset 요구, 예외 시 close를 검사한다.
- 실제 `NesEmulator` 경계: 프로세스당 하나만 허용하고 예외 종료 후 재생성할 수 있음을 확인한다.
- `uv run mypy src`로 공개 구현을 strict typecheck한다. 전체 테스트는 `FLYCADE_TEST_ROM='roms/Super Mario Bros. (Japan, USA).nes' uv run pytest`로 실행한다. ROM 변수가 없으면 실물 테스트는 명시적으로 skip하며 합성 성공과 구별한다.

브라우저는 T01에 구현하지 않는다. 부모 명세의 브라우저 사용자 흐름 검증은 후속 GUI 티켓 범위다. 진단 실패나 실물 실행 실패는 성공으로 승격하지 않으며 CLI 오류와 부분 보고서를 남긴다.

최종 검증: 실제 사용자 ROM을 활성화한 전체 테스트 **11 passed (6.18s)**, `uv run mypy src` **9개 소스 파일 통과**, `uv lock --check` 통과. `code-review`의 Standards/Spec 병렬 검토는 각각 발견 사항 0건이었다. Git 추적 파일에 `.nes`와 `.state`가 없음을 확인했다.

## 남은 검증과 범위

A1의 사용자 PC 진단·고정 1-1 실행·버튼/위치/종료 의미 검증을 완료했다. 자동 테스트는 전체 하드웨어 인수 기준을 대체하지 않는다. 다른 ROM/릴리스, 모든 월드/워프 경로, 모든 게임 사건의 조합, 다른 운영체제는 검증하지 않았다. 16픽셀 초과 순간이동은 보상을 주지 않고 계약 위반으로 중단한다.

실제 FlyWire 그래프 경로, sparse backward/optimizer, GPU 학습 성립, checkpoint 재개, 장시간 학습의 안정성·성능은 후속 티켓의 검증이다. 현재 보상·행동·전처리는 이 실측에 기반한 초기 실험값이고, 학습 효과를 입증한 설정이 아니다.
