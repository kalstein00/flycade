# T12 주기 평가와 평가본 비교

주기 평가는 초기 평가를 활성화한 Run에 적용한다. `configs/training-small.json`의 기본 간격은 1,000 optimizer updates이며 `evaluation_every_updates: 0`이면 자동 주기 평가만 끈다. 조건은 Run의 `initial-evaluation-protocol.json`으로 고정한다. 기본은 seed 11/22/33, 확률적 정책, 최대 1,800 emulator frames, 첫 에피소드 최대 15초 영상이다. 간격·개수·순차 CPU 선택 근거는 [A5 측정](A5.md)이다.

평가 경계에서 전체 상태와 정책 snapshot을 먼저 저장하고, trainer가 기다리는 동안 별도 CPU 프로세스 하나가 평가한다. 결과가 완성되어야 다음 평가 위치를 전진시킨다. 평가 실패 시 사전 저장본에서 다시 시작할 수 있고, 마지막 학습 update까지 끝난 경우에도 미완료 평가를 복구할 수 있다. Ctrl+C는 평가 프로세스의 정상 종료 또는 지정된 timeout을 기다린 뒤 안전 저장한다. 기본 timeout은 120초다. 평가 시간은 학습 시간에서 제외한다.

완료된 결과는 `evaluations RUN`으로 읽는다. `--refresh`는 공개 결과 파일에서 색인을 재구축한다. 동일 protocol에서 완료율, 평균 거리 순으로 최고본을 선택하고 동률이면 기존 최고본을 유지한다. protocol이 다르면 순위를 분리한다. 초기 정책, 최고·최근 평가 snapshot, 사용자 pin, 실행 중인 평가 참조는 보존 대상이다. 최근·최고 참조는 전체 체크포인트가 아직 존재할 때 자동 정리에서도 보호한다. 정책 전용 snapshot으로 평가한 뒤 이미 삭제된 전체 학습 상태가 되살아나지는 않는다.

```bash
uv run --offline --locked --extra graph --extra train flycade evaluations reports/my-run
uv run --offline --locked --extra graph --extra train flycade live reports/my-run
```

라이브 화면의 **평가 비교** 링크에서 초기·최근·최고 또는 개별 평가를 고른다. 두 평가본의 영상, 완료/평가 횟수, 거리 중앙값·범위·시드별 거리, 원래 보상을 함께 표시한다. Run/모델/snapshot/protocol과 평가 시각·진도를 확인할 수 있다. 영상은 실시간 평가 스트림이 아니라 완성된 고정 정책의 기록이며, 학습 화면의 회로를 합성하지 않는다. 회로 관측 이력이 없는 영상은 명시적으로 데이터 없음을 표시한다. 학습 화면은 평가 중임과 마지막 학습 표본임을 알린다.

분기는 평가 주기를 이어받되 부모 평가 결과를 자식 순위에 넣지 않는다. 부모 평가 색인·영상·정책 snapshot을 자식의 `origin/`에 독립 보관하고, 계승한 평가 ID와 부모 Run을 보고서에 기록한다. 자식의 평가 이력은 새 Run 식별자로 시작한다.

## 검증

CLI/프로세스와 영속 결과물, 로컬 HTTP/Chromium이라는 기존 승인 경계를 사용했다. fixture 검사는 평가 유무 간 모델·학습 RNG 동일성, 재개 후 주기와 이력, 동률·완료율 우선·거리 보조·protocol 분리, 최고본 보존, 분기, 최종 평가 복구, 평가 중 중단 후 추가 update 없음, 브라우저 선택/재생을 포함한다. 순위 규칙 검사의 조작된 보고서는 명시적 테스트 자료이며 실제 게임 성과가 아니다.

실제 NES/RTX5090 검증은 `reports/t12-comparison-002/run`, 결과는 [T12-evidence.json](T12-evidence.json)이다. 통합 검증용으로 예산 8 updates, 간격 4를 사용했다. 생산 권장 간격 1,000의 재측정이나 학습 향상 주장이 아니다. 초기/4/8 updates 각 3개 고정 시드 평가, update 4에서 별도 프로세스 재개, 브라우저 비교 및 재생을 확인했다. 화면 증거는 `t12-screens/`의 1920/1280/390px 캡처다.

3개 고정 시드는 작은 표본이다. 이 결과나 짧은 영상 하나로 일반 성과, 게임 클리어 능력, 모델 간 우열을 주장하지 않는다.

전체 회귀 검사 88개가 통과했다(505.66초). 검토에서 발견한 재개 직후 평가 중 종료 요청과 lease 등록 시점 문제를 수정했으며, 종료 회귀 실패를 먼저 확인한 뒤 관련 평가/재개/브라우저 검사 14개가 통과했다(119.83초). mypy는 31개 소스에서 오류가 없다. 코드 명세 재검토는 수정 사항 없음, UI 검토는 ship, 문서 검토는 기존 시스템 보존(No changes)이다. 스타일 검토의 비차단 개선 후보는 보호 참조 집합 중복과 참조 파일 API 집중화다. 신규 영상의 회로 표본·동기 재생 및 평가 관찰 스트림은 후속 #14 범위다.
