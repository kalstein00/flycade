# T06 — 게임·정책 입력·회로 활동·행동의 실시간 GUI

## 표본 계약

`train` / `resume --observe-hz 0|2|3|4|5`와 `live RUN --port 8766`가 공개 CLI 경계다. 기본 3 Hz는 실측을 위한 시작값이며 모니터 주사율이나 게임 fps가 아니다. 샘플링 주기는 monotonic clock으로 제한한다. 관찰용 forward를 추가하지 않고 **행동을 결정하는 forward**에만 읽기 콜백을 전달한다. optimizer와 bootstrap forward는 관찰하지 않는다. 최종 tanh 상태에서 표시할 노드만 detach하여 CPU로 복사하며 별도 추론·RNG 호출을 하지 않는다.

각 표본은 Run·세션·스트림(training)·worker(0)·에피소드·전체 전이 step·에피소드 내 step·정책 update·표본 시각을 포함한다. raw는 action 이전 `last_frame`, pixels는 실제 uint8 frame stack의 복사본이다. 노드 상태 벡터, 범주 확률, 실제 샘플링 행동, argmax, 버튼 매핑이 같은 forward에 속한다. env.step 이후 reward·RAM 진행·종료 사유는 `transition` 아래 분리한다. 학습 누적 지표는 별도의 `metrics_unix`를 가진다.

## 전달·상태·상한

trainer의 단일 관찰 스레드가 PNG/JSON 인코딩과 파일 교체를 담당한다. 대기 큐 1개, 스레드가 처리하는 표본 1개, 최신 파일 1개이며 최근 이력은 0개다. 다음 표본이 도착하면 대기 중인 이전 표본을 버린다. 디스크 파일은 같은 디렉터리의 임시 파일에 완성한 뒤 rename하므로 HTTP 소비자는 완성 표본만 읽는다. 관찰은 체크포인트가 아니므로 표본마다 fsync하지 않는다. 인코딩/쓰기 실패는 관찰 통계에 남기고 추가 수집을 중단하며 학습을 유지한다. 종료 시 관찰 writer join은 최대 2초다.

HTTP 서비스는 trainer와 별도 프로세스이며 쓰기 API가 없다. 브라우저 fetch는 한 번에 하나, 2초 timeout, 완료 후 200ms 뒤 재시도한다. 서버 연결도 2초 timeout이며 HTTP 대기열은 기본 5개다. 브라우저는 모든 이미지를 decode한 뒤 표본 DOM을 한 번에 바꾼다. 서버/브라우저 종료는 trainer 수명에 영향을 주지 않는다.

세션은 Run lock 아래 단조 증가 generation을 받는다. 브라우저는 Run 불일치, 과거 generation, 같은 generation의 다른 세션, 감소하는 sequence/step/정책 버전, 다른 stream/worker를 거부한다. 관찰을 끄고 재개하면 이전 표본을 disabled 상태로 무효화한다. 데이터 없음·첫 표본 대기·연결 끊김/재연결·2초 이상 표본 지연·정상 종료/저장·실패/프로세스 소멸을 구별한다. 데이터가 없거나 끊긴 동안 회로·이미지·확률은 움직이지 않는다. 표본 경과 시간은 계속 증가한다.

## 화면과 값의 의미

부모 #1 §6.1의 어두운 3열 게임45/회로30/상세25 배치를 사용한다. 1280×720과 1920×1080에서 핵심 정보에 접근 가능하며 좁은 화면은 세로로 배치한다. 게임 종횡비는 원본을 유지한다. 입력 프레임은 오래된 순이며 RGB/회색조·해상도·stack·정책 내부 /255 정규화를 표시한다. RAM 성과는 입력과 분리한다.

그래프별로 처음 한 번 계산한 구조도를 재사용한다. 실제 예제 입력→출력 경로의 처음·끝 각 32개, 입력/출력군 각 앞 12개, 인덱스 순의 연결 이웃 3회 탐색과 남은 인덱스로 최대 128개를 고른다. 그 노드 사이 실제 방향 연결의 앞 512개까지 표시한다. 사용/표시/제외 수·graph SHA·데이터 release·필터 기준을 제공하며 학습 topology는 바꾸지 않는다. 입력 원/내부 마름모/출력 사각형으로 색 이외의 군 구분을 제공한다. 활성색은 마지막 tanh 상태 벡터의 **부호 있는 산술평균**, 범위 −1~+1이다. 표시 노드 중 |평균|≥0.1의 수도 정의와 함께 표시한다. 발화나 생물학적 막전압으로 해석하지 않는다.

metrics는 완료된 update의 loss/entropy/학습 시간/속도와 표본 시점의 전이·진도·에피소드·메모리를 구분해 제공한다. RAM은 trainer process peak RSS, VRAM은 표본 시점 PyTorch allocated bytes이며 전체 GPU 또는 ffmpeg 포함 합산 사용량이 아니다. 마지막 체크포인트 ID가 있으면 표시한다. 노드 선택·시간 이력·평가 스트림 관찰·녹화와 회로 동기 재생은 #7의 후속 범위다.

## 검증

CLI 프로세스/파일 artifact, 실제 로컬 HTTP 서비스/Chromium, 정책 public forward 경계에서 검사한다. 관찰 on/off의 모델 tensor·Torch/Python/환경 RNG 일치, 전이 로그와 표본 확률/행동/보상/ID/관측 해시 일치, 전처리 PNG 디코딩 바이트 해시, 계산 가능한 3노드 회로의 실제 최종 상태, 브라우저 패널/표본 대응, 서비스 종료/재접속, 느린 소비자의 최신 표본만 수신, 이전 세션/정책/worker/역순 거부, 데이터 없음, 관찰 off 재개, 브라우저를 닫은 뒤 학습 완료를 검사한다. 합성 fixture를 NES 결과로 취급하지 않는다.

실제 NES/5090 측정과 화면은 아래에 별도로 기록한다. 이 짧은 실행은 A5의 빈도 후보 비교이며 1시간 안정성이나 학습 성과 개선을 입증하지 않는다.

## 실제 NES / RTX 5090 짧은 실행

로컬 `reports/t06-nes-5090-001/hz-{0,2,3,5}`에서 같은 실제 graph(4,622 nodes / 8,010 edges), seed, 32 updates × 32 transitions로 각 후보를 한 번 실행했다. 3 Hz 실행 중 Chromium을 연결해 1280×720, 1920×1080, 390×844를 캡처했다. 나머지는 producer 단독이다. 모든 실행이 1,024전이를 완료했고 녹화/관찰 오류는 없었다. 원시 집계는 [t06-evidence.json](t06-evidence.json).

단회·약 9초의 측정은 초기화·GPU 워밍업·동시 브라우저의 영향을 분리하지 못한다. 2 Hz가 off보다 빠른 결과도 있으므로 정밀한 오버헤드 추정이나 장기 예산 충족으로 해석하지 않는다. 기본 3 Hz를 유지하며 `--observe-hz`로 후보를 재측정할 수 있다. 선택된 forward 시간은 원래 추론을 포함하므로 관찰 추가 비용과 같지 않다. `encode_seconds`는 별도 writer의 PNG 인코딩 시간이며 파일 I/O 총시간이 아니다.

화면 문서화 검토: 기존 시스템 글꼴·한국어·기본 브라우저 조작과 읽기 전용 경계를 유지하는 기능 확장이다. 부모가 지정한 어두운 3열 관찰 화면을 적용하고, 1000px 이하에서는 게임을 전체 폭으로, 600px 이하에서는 모두 세로로 배치한다. PRODUCT.md와 기존 history.py에 전역 브랜드 변경을 가하지 않으며, DESIGN.md와 .impeccable/design.json은 기존 부재 상태를 유지한다.

최종 보완 후 `reports/t06-nes-5090-002/hz-3`에서 브라우저를 연결해 다시 확인했다. 실제 NES/CUDA 1,024전이·32 updates가 8.647초(118.43전이/초)에 완료됐고, 23개 표본·실측 2.72 Hz·최신 파일 72,240 bytes였다. 최종 화면 증거: [1280×720](t06-screens/t06-1280.png), [1920×1080](t06-screens/t06-1920.png), [390×844](t06-screens/t06-mobile.png). 모두 전체 페이지 캡처이며 실제 NES 화면이다. Chromium 자동화는 WSL/Linux에서 실행했고 Windows 네이티브 브라우저 자체를 자동화했다고 주장하지 않는다. Run·코드/그래프 해시·패키지와 캡처 해시는 evidence JSON에 기록했다.

리뷰: Standards 문서 위반 0건, 허용 빈도 중복 정의 제안 1건을 공통 설정으로 해결했다. Spec 발견 2건(긴 경로의 128노드 상한, 실행 중 producer를 포함한 느린 소비자 검증)을 회귀검사와 함께 해결했다. 화면 리뷰는 ship, 기존 시각 체계 확장에 대한 문서화 검토도 완료했다. 추가로 데이터 없음 응답이 관찰 off 세션의 generation을 지워 과거 표본을 되살리는 경우를 실제 서비스 브라우저 회귀검사로 막았다.
