# T10 — 실험 계보와 예산 연장

`branch`는 공개된 과거 정상 checkpoint UUID를 명시해 새 Run을 만든다. 모델·Adam optimizer·전체 RNG·누적 진도·저장 스케줄을 그대로 복사한다. 새 Run/세션/체크포인트 UUID를 부여하고 게임은 다음 resume에서 새 에피소드로 시작한다. 부모의 manifest·checkpoint·로그·제어 기록은 쓰지 않는다. 그래프와 초기 정책을 독립 복사하며, `origin/checkpoint.pt`와 `origin/run.json`에 부모 원본 바이트도 보존한다. 부모의 후속 보존 정리가 분기 출처를 잃게 하지 않는다. 새 Run의 initial은 조상의 초기 정책이며, 분기 시작 checkpoint와 구분한다.

`warm-start`는 전체 모델 state_dict를 엄격하게 로드한 뒤 새로운 TrainingConfig·Adam·RNG seed·0 진도·자동 저장 스케줄로 학습한다. 설정 파일이 없으면 새 실험 기본값을 사용하며 부모 학습 설정을 암묵적으로 상속하지 않는다. 게임 설정은 부모 기본값을 사용하고 `--config`로 새 설정을 지정할 수 있다. 그래프는 부모와 동일하다. state dimension/입력 채널처럼 가중치 모양이 달라지는 변경은 출력 디렉터리 생성 전 거부하며 임의 부분 로드하지 않는다. 새 초기 정책은 가져온 가중치이며 untrained라고 표시하지 않는다. manifest와 CLI 결과에 로드 범위 및 제외한 optimizer/RNG/진도/스케줄을 명시한다.

일반 `resume`은 기존의 전체 소스 해시·패키지·lock·Python/CUDA·manifest·graph·ROM/state·모델·게임 설정·state contract 검증을 그대로 적용한다. 현재 허용되는 코드/형식 변환 규칙은 없으며 다른 코드로 저장한 Run을 조용히 변환하지 않는다. 새 코드에서 이어가려면 해당 버전의 일치하는 로컬 실행 환경을 사용해야 한다.

`extend-budget RUN --updates TOTAL`은 writer가 없는 상태에서만 실행한다. TOTAL은 현재 총 예산보다 커야 하며 증가분이 아닌 새 총 update 수다. `budget.json`에 Run/사건 UUID·시각·원래/새 예산·현재 진도·기준 checkpoint·스케줄 규칙을 원자 기록한다. 기존 run.json과 checkpoint는 변경하지 않는다. resume은 연속적인 사건 체인을 검증하고 총 예산만 적용한다. 고정 학습률·optimizer step·누적 진도·다음 저장 시점을 재시작하지 않는다. checkpoint보다 오래된 예산 기록이나 잘못된 사건 체인은 명확히 거부한다. 분기는 부모의 현재 총 예산을 새 Run 최초 예산으로 삼으며 부모 예산 이력을 계보에 보존한다.

브라우저의 ‘Run 정보’는 전체 상태 분기·가중치 재사용·새 초기 실험, 전체 Run/부모/checkpoint ID, 총 예산 및 연장 이력을 표시한다. 아직 분기 학습을 시작하지 않아 관측 표본이 없는 상태에서도 확인할 수 있다.

```bash
uv run --offline --locked --extra train flycade checkpoints reports/parent
uv run --offline --locked --extra train flycade branch reports/parent --checkpoint <UUID> --output reports/branch
uv run --offline --locked --extra train flycade extend-budget reports/branch --updates 200000
uv run --offline --locked --extra train flycade resume reports/branch
uv run --offline --locked --extra train flycade warm-start reports/parent --checkpoint <UUID> --output reports/warm --training-config configs/training-small.json
uv run --offline --locked --extra train flycade live reports/branch
```

보존할 다른 과거 정상본은 부모가 실행 중이 아닐 때 `pin-checkpoint`로 별도 보호할 수 있다. branch는 생성만 하고 학습은 명시적 resume으로 시작한다. warm-start는 새 실험의 첫 학습을 바로 시작하며 `--stop-after-updates`로 한 세션 분량을 제한할 수 있다. 예산을 늘려도 성과 개선을 보장하지 않는다.

## 실제 NES 검증

`reports/t10-lineage-001`에서 실제 graph/RTX 5090으로 부모 update4→8을 실행했다. 과거 update4 정상본에서 분기하고 예산100000→100010을 기록한 뒤 update8까지 재개했다. 같은 부모 정상본의 warm start는 seed31·학습률0.0002·총예산8로 update4까지 새 학습했다. 두 작업 전후 부모의 47개 파일 해시가 모두 같았다. ## 검증 경계와 검토

공개 CLI/artifact 및 실제 HTTP/Chromium 경계의 관련23개 테스트가159.11초에 통과했다. mypy는28개 소스 파일에서 오류가 없었다. 독립 사양 검토는 누락·오구현0건, 화면 검토는6개 캡처에서 ship 판정이었다. 표준 검토의 비차단 개선 제안1건은 세 진입점의 짧은 ‘체크포인트보다 오래된 예산’ 검사 중복이다. 현재 세 조건이 동일하고 각 진입점의 명시적 방어이므로 유지했다. 화면은 기존 시스템의 일반 확장이며 documenter는 별도 디자인 파일 변경이 필요 없음을 확인했다.
