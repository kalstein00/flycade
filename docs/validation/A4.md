# A4 — 전체 학습 상태 재개와 압축 플레이 기록

## 계약

T04/#5의 안전 경계는 `optimize`가 전체 PPO epoch의 Adam step과 유한 파라미터 검사를 마친 뒤다. rollout 종료를 optimizer 완료로 간주하지 않는다. 예산 완료, `--stop-after-updates`, Ctrl+C 저장 종료가 이 경계에 도달한 뒤 체크포인트를 쓴다.

체크포인트 형식 1에는 모델의 parameter와 buffer(COO 그래프 포함), Adam state, 전체 학습/게임 설정과 고정 예산, Python/NumPy/Torch CPU/CUDA RNG, Gym 환경·행동/관측 space RNG, 누적 전이·프레임·optimizer/rollout 갱신·완료 에피소드/종료 사유·누적 학습 시간이 있다. 정책 샘플러는 Torch RNG를 사용하며 batch 순서 무작위화가 없다. 학습률은 고정이다. 전역 running normalization, AMP scaler, 순환 hidden state, 환경별 정규화 할인 return, 주기 평가·저장은 현재 알고리즘에 없으며 `state_contract`에 명시한다. 소비한 rollout과 GAE는 저장하지 않는다.

재구성 시 모델/optimizer/환경을 먼저 만들고 난수를 복원한 뒤 seed 없이 새 에피소드를 reset한다. 프레임 스택·위치/최대 진행·이전 RAM·타이머·무진행 카운터는 초기화하며, 행동은 stateless 버튼 마스크다. 중단 에피소드를 성공/사망으로 집계하지 않는다. 전역 누적 진도는 보존한다. 시간 순환 상태가 없는 정책은 관측마다 영 상태로 시작한다.

Run의 설정·코드/패키지 버전·graph/ROM/state/초기 모델 식별을 로드 전에 검사한다. 형식/핵심 설정 변경, 필수 artifact 누락/변조, 코드 해시·Python·패키지·lock·CUDA runtime 불일치를 거부한다. 현재 코드 호환 규칙은 **Python 파일 전체의 동일 해시**다. Git SHA는 출처 정보이며 문서 커밋은 호환성을 깨지 않는다. 정책은 `strict=True`로 로드한다. A3 snapshot의 자동 마이그레이션이나 조용한 부분 로드는 없다.

## 원자 저장과 세션

임시 체크포인트 작성 → flush/fsync → CPU 재읽기 검증 → 해시 → 고유 ID의 정상 파일로 rename → directory fsync → metadata → `latest.json` 원자 교체 순서다. `latest.json`이 공개 경계다. `final.pt`는 A3 도구용 편의 symlink이며 resume 선택 기준이 아니다. 이전 체크포인트는 보존하고 임시본을 재개 대상으로 사용하지 않는다. 정상본 손상 시 자동 fallback·보존 수량 정책은 후속 범위다.

Run의 새 세션마다 UUID와 시작 갱신 수·부모 체크포인트를 기록한다. Linux flock으로 동시 writer를 막고 프로세스 종료 시 해제한다. 로그에도 Run/세션 ID를 붙인다. 재개 진도는 로그 합산이 아니라 정상 체크포인트에서 복원하므로 실패 세션의 미저장 step을 이중 합산하지 않는다.

## 영상 및 브라우저

FFmpeg libvpx-vp9, CRF 45, bitrate target 0, 12fps, yuv420p, 무음으로 원본 NES RGB 화면을 저장한다. [FFmpeg codec 문서](https://ffmpeg.org/ffmpeg-codecs.html#libvpx)와 설치 인코더를 확인했다. 화질보다 압축을 우선하지만 인식 불가능한 최저 화질을 목표로 삼지는 않는다. 실제 게임 5프레임당 1장을 기록하므로 벽시계 학습 속도와 재생 속도는 독립적이다. 마지막 구간의 시간 반올림은 최대 1/12초다.

최대 720개 인코딩 프레임(60초)마다 독립 WebM을 완성하고 fsync/rename 후 목록에 공개한다. raw frame 전체를 쌓지 않고 한 프레임과 OS pipe만 사용한다. 인코더는 1 thread, pipe 대기 10초, 종료 대기 30초로 제한하며 timeout/인코더 실패는 프로세스 kill/wait와 임시 파일 정리 후 녹화 오류로 보고한다. 학습 체크포인트는 별도로 보존한다. 완성 영상은 자동 삭제하지 않는다. 무한 디스크 용량을 보장하지 않으며 사용자가 이전 영상을 제거할 수 있다.

`history --serve`는 loopback의 읽기 전용 HTTP 서비스다. 녹화 시각·세션 시작 진도·구간·재생 시간·용량을 표시하고 native video controls로 재생·탐색한다. 각 영상은 Run/세션 ID와 연결되며 학습 중 변하는 정책의 기록이다. 고정 체크포인트 평가 영상이나 회로 활동 동기 재생을 주장하지 않는다.

## 검증

2026-10-10 실제 NES/RTX 5090, A2의 4,622 뉴런/8,010 edge 그래프로 4 rollout × 4 transition, Adam 8 step을 실행했다. `max_frames=16`으로 rollout 경계에서 같은 새 에피소드 조건을 만들었다. 연속 4갱신과 2갱신 저장·종료 후 새 프로세스 2갱신을 비교했다. 모델과 optimizer의 사전 허용 오차는 atol/rtol 1e-5, 실제 모델 최대 절대 차이는 **0.0**이었다. 이는 통제된 짧은 경로의 결과이며 일반 CUDA bitwise 재현 보장은 아니다.

실행 원본: `reports/a4-nes-5090-002/`. 축약 증거: [a4-evidence.json](a4-evidence.json). 같은 Run ID, 다른 세션 ID, 정상 환경 종료, VP9 영상 2개를 확인했다. 총 영상 용량은 12,728 bytes였다. 실제 학습 성능 향상, PC/WSL 재시작(AC-07), 1시간 자원 검증(AC-12)은 이번 판정에 포함하지 않는다.

CPU CLI fixture에서는 새 프로세스 재개 후 모델/buffer/optimizer/Torch RNG의 정확한 일치와 동일한 reset 조건의 다음 갱신을 비교한다. 설정/형식 변경·artifact 누락·손상 거부, 중단 에피소드 미집계, SIGINT 안전 경계 및 인코더 자식 PID 소멸, 파일 크기 제한을 이용한 쓰기 실패에서 이전 정상본 보존·재개, 인코더 실패와 학습 저장 분리를 검사한다. 브라우저에서는 실제 로컬 서비스의 두 세션 영상 선택·재생·탐색·새로고침 및 체크포인트 불변을 검증한다. 작은 fixture의 통과와 실제 NES/GPU 결과를 구분한다.

## 재현 명령

README의 train/resume/history 최소 경로를 사용한다. CPU 자동 검사에서 graph fixture를 생성한다. 실제 GPU 통제 비교는 `{"max_frames":16}` 게임 설정, `--updates 4 --rollout-steps 4`로 별도 control Run과 `--stop-after-updates 2` Run을 만들고 후자를 새 CLI에서 resume한다. 전자의 최종 모델/optimizer와 비교한다. 실제 로컬 ROM 등록과 A2 graph가 필요하고, 모든 실행에 `uv run --offline --locked --extra graph --extra train`을 사용한다.
