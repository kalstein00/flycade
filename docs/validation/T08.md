# T08 — 매일 학습·저장·재개

제어 경계는 CLI, 관찰 경계는 기존 읽기 전용 브라우저다. `train --training-config configs/training-small.json --initial-evaluation-config configs/evaluation-small.json`으로 무학습 평가를 남긴 후 본 학습을 시작한다. 자동 저장 기본600초는 누적 학습 시간에 적용하며 `TrainingConfig.autosave_seconds`를 JSON으로 변경할 수 있다. 종료/재개 사이의 PC 유휴 시간은 포함하지 않는다.

`save RUN`은 요청을 원자적으로 전송하고 정상본 공개까지 기다린다. `save RUN --stop`은 저장과 환경/인코더 종료까지 기다린다. `--wait-seconds 0`은 요청 ID를 즉시 반환하며 이후 `status RUN`으로 확인한다. 대기 제한을 넘겨도 요청을 취소하거나 학습 프로세스를 강제 종료하지 않는다. 기본 대기30초는 `--wait-seconds`로 조절한다. 첫 Ctrl+C도 같은 안전 경계 저장을 사용한다.

요청 파일은 한 개만 허용하고 수동 요청별 완료 결과를 `save-results/`에 보존한다. 자동 저장 중에는 수동 요청 하나를 대기시키며, 수동 요청이 이미 있으면 `save_pending`으로 알리고, 실행 중 writer가 없으면 `run_inactive`로 거부한다. trainer만 모델·optimizer를 저장한다. 별도 CLI 요청은 실행 중 trainer의 현재 세션에 묶이며 PID 재사용으로 다른 프로세스에 신호를 보내지 않는다. kernel flock이 단일 writer를 보장하며 종료 후 남은 `.writer.lock` 파일은 점유가 아니다. 평가/관찰은 이 writer lock을 요구하지 않는다.

`control.json`과 `save-events.jsonl`은 요청 시각→`waiting_boundary`→`saving`→`complete` 또는 `failed`를 기록한다. `last_save`는 마지막 정상본의 UUID·update·전이·시각이다. 종료 시 `active=false`를 기록하고, 강제 종료의 stale 상태는 `status`에서 실제 lock 점유 여부로 구별한다. 브라우저는 관측이 없거나 꺼져도 이 제어 상태를 별도로 표시한다. 표본의 정책 시점과 저장 상태 시점은 서로 구별한다.

매 저장은 rollout 전체의 PPO epoch 갱신이 끝난 뒤 수행한다. 다음 자동 저장 시각은 누적 학습 시간 단위로 체크포인트에 보존한다. 지연으로 여러 주기를 놓치면 다음 미래 주기로 진행하고, 같은 rollout을 다시 학습하지 않는다. 상수 학습률/전체 예산/누적 지표를 유지한다. 재개는 같은 Run의 새 세션이며 게임은 새 에피소드로 시작한다. 중단된 에피소드를 성공/사망으로 세지 않는다.

인코더 쓰기 대기는10초, 종료 대기는30초로 제한한다. 실패 시 해당 프로세스 그룹을 정리하고 영상 오류를 기록하되 안전 체크포인트를 보존한다. 정상 종료 후 encoder와 환경을 닫은 다음 저장 후 종료 요청에 완료를 응답한다.

## 매일 운영

1. 시작 전 `diagnose`와 A5 자원 예산을 확인한다. 처음에는 새 경로에 본 학습을 만들고, 다음 날부터는 `resume RUN`을 사용한다.
2. 다른 터미널에서 `live RUN`을 실행한다. 브라우저를 닫아도 학습은 계속된다. 녹화 재생의 일시정지는 학습 제어가 아니다.
3. 즉시 복구 시점을 남기려면 `save RUN`, 오늘 학습을 마치려면 `save RUN --stop` 또는 trainer 터미널의 Ctrl+C를 사용한다.
4. `status RUN`의 `state=complete`, `active=false`, 마지막 저장 시각과 update를 확인한 다음 WSL/PC를 종료한다. 실제 WSL/PC 재시작 확인은 #17에서 수행한다.
5. 다음 날 동일 코드/패키지/ROM/graph 조건에서 `resume RUN`을 실행하고 새 세션·누적 update 증가를 확인한다. 소스 변경은 호환 검사에서 거부된다.

손상된 최신본의 자동 이전본 복구와 보존 수 제한은 #10 범위다. 이 단계는 기존 정상본을 삭제하지 않는다.

## 실제 실행과 브라우저 증거

`reports/t08-daily-003`에서 실제 NES·RTX5090·A5 graph로 초기 평가 후 자동 저장(검증용2초), 수동 저장(update20/640전이), 저장 후 종료(update26/832전이), 새 프로세스 재개(update30/960전이)를 수행했다. [결과와 저장 사건](T08-evidence.json)에 Run/세션·요청·checkpoint·누적 지표를 남겼다. 초기001 시도는 자동 저장과 수동 요청 충돌로 `save_pending`이 발생했다. 자동 저장 중 수동 요청을 대기시키고 요청별 결과를 보존한 뒤002로 재검증했다. 초기 평가 timeout/종료 정리 표시 보완까지 적용한 최종003을 증거로 보존한다. 이 짧은 운영 검증은 A5 성능 재측정이나1시간 인수가 아니다.

실제 로컬 HTTP와 Chromium에서 저장/종료/복구 시점/새 에피소드 안내를 확인했고 1280×720·1920×1080·390×844에서 가로 넘침 없이 표시했다. [1280 화면](t08-screens/daily-1280.png), [1920 화면](t08-screens/daily-1920.png), [모바일 화면](t08-screens/daily-390.png)은 실제 Run 캡처다. detector의 이미지 src 경고1건은 실행 시 원본 픽셀을 주입하는 비활성 template이며 실제 표시와 decode 검사로 확인했다.

초기 평가 중에도100ms 간격으로 저장/종료 요청을 확인한다. 첫 Ctrl+C 또는 수동 종료 요청은 초기 평가가 끝나고 첫 rollout 갱신이 완료된 안전 경계에서 저장한다. 평가 대기는 기본120초(`evaluation_timeout_seconds` 설정)로 제한하며 초과 시 evaluator와 그 인코더 자손을 강제 정리하고 실패/정리 여부를 기록한다. 첫 학습 전 평가 실패라 정상 resume 체크포인트가 아직 없으면 새 Run으로 다시 시작해야 하며 초기 정책은 보존한다. 이 대기는 기본 CLI 대기30초보다 길 수 있으므로 `status` 또는 더 긴 `--wait-seconds`로 확인한다.

정상본 공개 뒤 환경/영상 종료 중에는 브라우저가 **저장 완료 · 종료 정리 중**과 요청 이후 경과 시간을 표시한다. `active=false`가 된 뒤에만 종료 완료로 바뀐다. 외부 인코더의 EOF 이후3초 지연을 실제 프로세스로 주입한 브라우저 검사에서 두 상태 전환을 확인했다. [정리 중 화면](t08-screens/closing-fixture.png)은 명시적 CPU 합성 환경 검사다.
