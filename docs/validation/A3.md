# A3 — 실제 커넥톰 정책의 NES 경험 수집과 갱신

2026-10-10 사용자 WSL에서 T03/#4를 검증했다. **A3, AC-03, AC-04 통과**: 실제 FlyWire 부분 그래프의 행동 분포 영향과 NES 경험으로 RTX 5090에서 학습 파라미터 갱신을 확인했다. 행동 성능 개선·스테이지 완료·장기 안정성은 판정하지 않는다.

## 모델과 학습 후보

PyTorch **2.10.0 / CUDA runtime 12.8**, CPython 3.12.9, Stable-Retro 1.0.1, Gymnasium 1.4.0을 사용했다. 설치 패키지 및 NVIDIA 라이브러리는 `uv.lock`에 고정했다. GPU는 NVIDIA GeForce RTX 5090, 드라이버 610.57.01이다.

[PyTorch 2.10 sparse.mm 문서](https://docs.pytorch.org/docs/2.10/generated/torch.sparse.mm.html)의 COO × dense 미분 경로를 사용한다. GPU 인식만 확인하지 않고 실제 모델의 forward, 인코더까지의 backward, Adam 갱신을 모두 실행했다. 구조 연결은 고정하지만 sparse 결과를 detach하지 않는다. CSR·sparse × sparse·학습 edge의 모든 조합이 지원된다고 주장하지 않는다.

[OpenAI PPO-Clip 설명](https://spinningup.openai.com/en/latest/algorithms/ppo.html)을 기준으로 clipped surrogate, GAE, 가치 회귀, entropy 항과 gradient clipping을 직접 구현했다. 작은 전체 rollout batch를 반복 갱신하고 안전 경계가 명확하게 드러나도록 PyTorch만 채택했다. SB3는 설치하지 않았다. 일반화된 PPO 라이브러리 대체나 학습 성능 검증을 뜻하지 않으며, A4 복원 및 A5 운영 측정 전 최종 라이브러리·규모는 확정하지 않는다.

모델은 4×84×84×3 uint8 픽셀 → Conv2d/tanh/4×4 pooling/linear 인코더 → 입력 노드 → 실제 방향성 COO 그래프 → 출력 노드 전체를 펼친 actor/critic이다. 인코더 입력은 /255 고정 변환이고 RAM은 보상·로그 전용이다. 기본 상태 차원 8, 관측마다 영 상태에서 시작해 2회 전파하며 매회 같은 입력 drive를 넣는다. 입력군과 출력군은 겹치지 않아 출력에 도달하려면 실제 연결을 거쳐야 한다. 출력이 충분한 전파 횟수 안에 도달하지 못하면 Run 생성을 거부한다.

고정된 양수 synapse count를 도착 뉴런별 유입 합으로 정규화한다. 신경전달물질에서 생물학적 부호를 추론하지 않으며 이 매핑은 공학적 정책이다. 학습 파라미터는 encoder의 convolution/linear와 actor/critic의 weight/bias 8개 tensor다. topology와 graph weight는 buffer이며 시간 순환 상태·사전학습·교사 정책은 없다.

## 실제 NES·5090 증거

사용한 실제 그래프는 A2의 4,622개 뉴런, 8,010개 방향성 연결, L1→Mi1→T4a 부분 그래프다. 그래프 해시는 `97ea609f3c64c24ebfd90c73b4590878d437b5e67851dff1f60f9e74c730de7f`다. 원본 출처·graph artifact 해시·모델/학습/게임 설정·코드 파일 해시·패키지 버전·Run/세션 UUID·ROM/state 식별은 [기계 판독 기록](a3-evidence.json)에 있다. 실제 Run과 전체 로그·초기/최종 모델은 Git에서 제외한 `reports/a3-nes-5090-003/`에 보존했다.

```bash
uv run --offline --locked --extra graph --extra train flycade train \
  --graph .flycade/graphs/visual-a2-final-001 \
  --output reports/a3-nes-5090-003 --updates 16 --rollout-steps 64
```

| 항목 | 실측 |
| --- | ---: |
| 환경 전이 | 1,024 |
| 에뮬레이터 프레임 | 4,085 |
| 완료된 PPO rollout 갱신 / Adam step | 16 / 32 |
| 완료 에피소드 | 5 (사망 4, 무진행 1) |
| 실행 중 최대 진행 거리 | 1,214 pixels |
| 누적 보상 | 3,219 |
| 학습 시간 / 전이·초 | 8.445초 / 121.26 |
| 마지막 loss / entropy | 11.3756 / 0.3319 |
| 프로세스 peak RSS | 2,358,026,240 bytes |
| PyTorch peak GPU allocated | 161,337,344 bytes |

시간은 환경 생성·control 검증·rollout·갱신·로그를 포함하며 패키지 import·모델 생성·최종 파일 저장은 제외한다. wall 시간도 따로 기록한다. RSS는 Linux 프로세스 수명 최고값, GPU 수치는 PyTorch 할당 최고값이며 GPU 전체 사용량/상주 context/다른 프로세스 포함 VRAM 상한이 아니다. 이 짧은 실측은 A5의 10~15분이나 AC-12의 1시간 검증을 대체하지 않는다.

고정된 첫 관측과 초기 모델에서 연결을 모두 제거했을 때 행동 확률의 최대 절대 차이는 **0.01095724**였다. 동일 공개 `ConnectomePolicy.forward`를 호출하고 같은 파라미터와 픽셀에서 edge 전파만 0으로 바꿨다. 입력 해시와 두 분포 전체를 기록했다. 작은 CPU 경로 제거/역방향 사례도 같은 실제 학습용 클래스를 사용한다. 이 결과는 연결이 행동 계산에 참여한다는 증거이며 구조 우월성 증거가 아니다.

모든 1,024개 전이의 행동 범위·확률 합·유한 보상, 16개 갱신의 유한 loss를 별도 확인했다. 8개 학습 tensor 모두 초기/최종 파일을 CPU로 읽어 유한한 변화량을 확인했고 optimizer 상태의 step도 모두 32였다. 각 갱신의 encoder gradient norm은 0보다 컸으므로 고정 edge를 통과한 미분 경로가 유지됐다. 초기 모델은 첫 행동 전에 읽기 전용으로 저장하고 파일 해시가 그대로임을 확인했다. 종료 시 `safe_boundary=true`, `environment_closed=true`다. 환경은 같은 프로세스에 하나이고 자식 worker를 생성하지 않는다.

## CPU 자동 검증과 안전 경계

부모 #1에서 합의한 CLI 프로세스/artifact 및 실제 정책의 공개 픽셀/행동 분포 경계를 사용한다. CPU 합성 에뮬레이터를 사용한 Run은 보고서에 `synthetic CPU fixture; not NES/GPU acceptance`로 구분한다.

- 연결 제거 시 분포 변화, 역방향 경로의 차단, 실제 인코더까지의 유한 gradient.
- 새 CLI Run의 식별·초기 보호·실제 파라미터 변화·기존 디렉터리 덮어쓰기 거부.
- 설정 JSON의 budget/seed 반영, 전파 횟수 부족 거부, 3-edge fixture로 [2,E] artifact 해석 확인.
- 에뮬레이터 프레임 중간의 외부 시간 제한과 에피소드/전이 카운터, optimizer 상태와 모델 artifact 확인.
- 비정상 loss에서 갱신 완료를 주장하지 않고 오류 및 환경 종료를 기록.

안전 경계는 rollout 수집 후 해당 모든 PPO epoch의 optimizer step과 유한 파라미터 확인이 끝난 시점이다. `updates.jsonl`과 최종 snapshot은 이 이후에 쓴다. 실제 terminal에서는 bootstrap 0, truncation에서는 마지막 관측 가치를 쓰고 GAE 누적은 양쪽 모두 reset 전에 끊는다. 예산 종료 중이던 에피소드는 완료로 세지 않는다.

`final.pt`는 A3 확인용 모델·optimizer·RNG·진도 snapshot이다. 원자 저장·수동 저장 요청·첫 Ctrl+C 이후 안전 저장·새 프로세스 resume·손상 복구는 후속 T04 범위이며 이번에 검증했다고 보고하지 않는다. Ctrl+C와 예외는 환경을 닫고 부분 보고서를 남긴다. 브라우저 관찰은 이 티켓에 없으며 별도의 GUI 통과 주장을 하지 않는다.

## 남은 실험 결정

PPO hyperparameter·더 큰 그래프·입출력 매핑·노드 상태 차원·장기 처리량의 최적값은 미정이다. 기본 full-rollout batch의 메모리는 rollout 길이에 비례한다. CUDA bitwise 결정론을 보장하지 않으며 동일 seed를 고정하는 것과 동일 하드웨어에서의 완전한 재현은 구별한다. 실행 중 성과 수치는 고정된 초기 정책과 후속 정책의 독립 평가가 아니므로 개선으로 해석하지 않는다. 다음 단계는 A4 복원과 A5 관찰·저장·평가를 포함한 예산 측정이다.
