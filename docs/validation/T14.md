# T14 별도 CNN Run과 작은 동일 조건 비교

`train --model-kind cnn` 또는 training JSON의 `model_kind: "cnn"`으로 무학습 CNN Run을 만든다. 기본값은 `connectome`이다. 두 모델은 동일한 train/save/resume/branch/warm-start/evaluate, 초기/주기 평가 및 영상·관찰 기록 경로를 사용한다. 기본 경로에는 교사나 사전학습 가중치가 없다. 명시적 warm start는 부모 가중치 재사용임을 기존 lineage에 기록한다.

CNN은 Conv16(kernel8/stride4)→ReLU→Conv32(kernel4/stride2)→ReLU→adaptive pool3×3→dense64→ReLU→actor7/critic1이다. 입력은 같은84×84 RGB4프레임 uint8 및 /255 정규화이며 시간 순환은 없다. CLI는 공통 Run 준비를 위해 동일한 graph artifact를 받지만 CNN은 그래프를 계산에 사용하지 않으며 `model.graph_used=false`와 `graph_influence.applicable=false`를 기록한다. `state_dim`과 `propagation_steps`는 커넥톰 전용 설정으로 CNN 계산에 쓰이지 않는다.

```bash
uv run --offline --locked --extra graph --extra train flycade train \
  --graph .flycade/graphs/visual-a2-final-001 --output reports/cnn-run \
  --training-config configs/training-small.json --model-kind cnn \
  --initial-evaluation-config configs/evaluation-small.json
uv run --offline --locked --extra graph --extra train flycade compare-runs \
  reports/connectome-run reports/cnn-run
uv run --offline --locked --extra graph --extra train flycade live \
  reports/connectome-run --run reports/cnn-run
```

`compare-runs`는 공통 protocol만 비교한다. 여러 protocol이 공통이면 `--protocol <ID>`로 고른다. 게임/ROM/state/전처리/행동/보상/시드/평가 횟수는 protocol로 확인하고, 총 updates·rollout steps·epochs·예정 전이 수가 같은지 별도로 보고한다. 모델 종류를 포함한 training 설정 차이와 원래 학습 game 설정 차이(`game.<key>`), 파라미터 수도 남긴다. 평가의 프레임 한도가 같아도 원래 학습 에피소드 한도가 다르면 차이를 표시한다. 예산이 다르면 `same_training_budget=false`이며 동일 예산이라고 주장하지 않는다. 같은 조건의 초기 평가가 없으면 먼저 초기 snapshot 평가를 요구한다.

브라우저는 Run을 전환하여 각 모델의 초기·후속 결과/영상을 비교한다. 모델명·예산·파라미터 수, 초기 대비 평균 거리·완료율·사망 횟수 변화를 표시한다. CNN의 학습/평가 관측과 재생 화면에는 **회로 해당 없음**을 표시하고 가짜 뉴런/연결/활동 이력은 만들지 않는다. 실제 입력·행동 확률·행동 이력은 계속 볼 수 있다.

## 실제 NES 작은 비교

두 Run은 `reports/t14-cnn-001/{connectome,cnn}`이다. 동일 RTX5090, 등록된 NES/state, 16 updates ×32 transitions =512전이, epochs2, seed7, 초기/8/16 updates의 같은 stochastic protocol(seed11/22/33, 최대1800 frames, 첫 영상15초)을 사용했다.8 updates에서 종료 후 새 프로세스로 재개했다. 설정 차이는 모델 종류이고, 모델 용량은 의도적으로 동일하지 않다.

| 모델 | 파라미터 수 | 초기 평균 거리 | 후속 평균 거리 | 변화 | 완료 초기→후속 | 사망 초기→후속 |
|---|---:|---:|---:|---:|---:|---:|
| 커넥톰 | 1,724,040 | 518.33px | 786.67px | +268.33px | 0/3→0/3 | 2/3→2/3 |
| CNN | 39,544 | 596.33px | 451px | −145.33px | 0/3→0/3 | 1/3→1/3 |

**CNN은 이 작은 표본에서 평균 거리가 감소했다.** loss나 가중치 변화만으로 행동 학습 성공을 선언하지 않는다. 커넥톰의 거리 증가도3개 고정 시드·짧은 예산·서로 다른 모델 용량의 결과여서 일반화, 클리어 능력, 커넥톰 우월성의 증거가 아니다. 원자료는 [T14-evidence.json](T14-evidence.json)에 있다.

이상이 있으면 Run의 ROM/state/integration 식별자, 평가 `transitions.jsonl`의 원래 보상·종료 사유, 입력/행동 재생 기록, 모델별 입력 매핑, 행동 확률·entropy 및 `updates.jsonl`의 loss/optimizer 기록을 함께 조사한다. 초기 snapshot과 각 평가 protocol/seed를 사용해 같은 정책을 다시 평가할 수 있다.

## 검증

합성 CPU fixture는 공통 lifecycle·프로토콜·예산 비교, 예산 불일치 표시와 미공유 protocol 거부, 분기/가중치 재사용 모델 식별, CNN 회로 해당 없음과 입력/행동 유지, 브라우저 재생·크기별 overflow·checkpoint 불변을 검사한다. 기존 동기 재생과 함께9개 대상 검사가 통과했다(70.03초). mypy34개 소스에서 오류가 없다.

실제 NES 검증은 별도로 위 두 Run에서 수행했고, 브라우저 모델 전환·CNN/커넥톰 회로 구분 및 영상 재생을 확인했다. 화면은 `t14-screens/`의 CNN live/compare 1920·1280·390px와 replay1280px다. 작은 비교 결과와 플랫폼 기능 검증을 구분한다.

최종 전체 회귀 검사: 97 passed (570.64초). 리뷰에서 발견한 원래 학습 game 설정 차이 누락을 회귀 테스트로 재현하고 수정했으며, 관련 CLI 2개 검사와 mypy34개 소스가 통과했다. 명세 재리뷰와 UI 리뷰는 통과했고 디자인 문서 변경은 필요하지 않았다.
