# T16 장시간 실행과 실제 재시작 인수

상태: **진행 중**. 실제1시간 실행 및 사용자 WSL/PC 재시작·Windows 화면 인수를 아직 완료로 표시하지 않는다. 운영 절차는 [운영 안내](../OPERATIONS.md)에 모았다.

## 재현

```bash
uv run --offline --locked --extra graph --extra train python scripts/acceptance_run.py \
  --output reports/my-new-acceptance --seconds 3605
```

실제 NES·커넥톰·CUDA를 사용하고 `configs/preset-small.json`의 설정을 따른다. 스크립트는 학습·관찰·초기/주기 평가·압축 영상/관찰 이력·자동 저장을 포함해 최소3600초를 요구한다.학습 시작 전부터 저장·종료 완료 후까지 독립 sampler가 목표1초 간격으로 프로세스 트리 RSS/swap·Linux 여유 메모리·GPU 전체 사용량,1분 간격 Windows 여유 메모리, update별 학습시간 간격,5분 간격 브라우저 뉴런 탐색·재접속·비교/재생을 기록한다. 마지막에는 CLI 저장·종료 완료까지 측정한다. 원시 근거는 지정 출력 디렉터리에 남는다.

`boot-id-before.txt`는 재시작 전 WSL kernel boot ID이다. 실제 재시작 후 이 값과 `/proc/sys/kernel/random/boot_id`가 다름을 확인하고, 정상 저장 checkpoint ID와 새 session ID·추가 진도를 기록한다. 이 스크립트 자체는 WSL이나 PC를 재시작하지 않는다. WSL Chromium 자동 검사는 Windows 화면 수동 인수를 대신하지 않는다.

## 사용자 수동 단계

자동 실행과 정상 저장을 마친 다음 진행한다. 실행 중인 WSL을 임의로 종료하지 않는다.

1. Windows PowerShell에서 `wsl --shutdown`을 실행하거나 PC를 재시작한다.
2. WSL을 다시 열고 이 프로젝트로 돌아와 재시작 완료를 알려 준다. 에이전트가 boot ID 변경, 동일 checkpoint 재개·추가 업데이트·새 세션을 검증한다.
3. 로컬 `live` 주소를 Windows 브라우저에서 열어 게임·입력·회로·행동·저장 상태를 확인한다. 뉴런 선택과 필터, 브라우저 닫기/재접속, 초기·최신·최고 영상 비교, 재생·일시정지·탐색을 확인한다.
4. 인터넷 연결을 끊은 상태에서 준비된 로컬 Run의 재개·평가·보호 영상/관찰 이력이 열리는지 확인한다. 확인한 환경·시각·성공/실패를 남긴다.

사용자 확인 전에는 AC-07 및 실제 Windows 화면 항목을 통과로 표시하지 않는다. 플랫폼 기능 검증과 게임 행동의 성과는 별도로 보고하며, 미개선 결과도 그대로 남긴다.

초기 시도 `reports/t16-acceptance-001`은 첫 갱신 전 보고서 접근으로6 updates에서 안전 종료했다. `002`는 sampler를 브라우저 조작과 분리하기 위해264 updates에서 정상 종료했다. 둘 다1시간 인수 근거가 아니다. `003`은 보고서 갱신 중 부분 읽기를 발견해707 updates에서 정상 저장됐다. 보고서 읽기에 제한된 재시도를 추가했으며 새 측정은 `reports/t16-acceptance-004`에서 수행한다. 재현할 때는 존재하지 않는 새 출력 경로를 사용한다.

재시작 전 정상본은 `restart-handoff.json`에 checkpoint ID·해시·session ID·누적 카운터·boot ID를 기록하고 pin한다. 실제 재시작 후 다음 도구가 같은 boot ID를 거부하고, 동일 정상본에서3 updates를 추가한 뒤 새 session·optimizer step·전이 수를 검증한다.

```bash
uv run --offline --locked --extra graph --extra train python scripts/verify_restart.py \
  reports/t16-acceptance-004/restart-handoff.json
```

짧은 실행의 인수 거부와 같은 boot의 재시작 인수 거부를 CLI 경계에서 검사했다(2 passed,0.19초). mypy37개 소스 통과. 이는 실제 재시작 성공 검증을 대체하지 않는다.
