# T05 — 고정 정책 평가와 초기 플레이 기록

## 공개 계약

CLI의 `evaluation-protocol`, `evaluate`, `compare-evaluations`와 기존 `history --serve`를 사용한다. `train --initial-evaluation-config`는 모델 생성 후 첫 rollout 전에 초기 평가를 별도 CPU 프로세스에서 마치고 진행한다. 대기 상태를 stderr와 `report.json`의 `evaluating_initial`/`training_paused`로 알린다. 기본 학습 시간에서는 평가 대기 시간을 제외하며, 평가 자체의 시간과 자원을 따로 기록한다. 초기 평가를 요청하지 않은 기존 train 경로도 유지한다.

`initial.pt` 및 `snapshots/<ID>.pt`는 정책 parameter/buffer만 담고 읽기 전용이다. 후속 snapshot은 해당 optimizer 갱신 완료 체크포인트 ID와 연결된다. 가중치 파일 저장·재읽기·fsync를 끝내고 불변 metadata를 공개한 뒤 `snapshots/latest.json`을 교체한다. 평가의 `latest` 선택은 이 포인터를 한 번 읽어 고정한다. 평가를 위해 optimizer 또는 전체 resume 체크포인트를 로드하지 않는다.

snapshot은 Run manifest 해시·정책 가중치 해시·graph·모델·학습 진도와 연결된다. 평가 전 정책/환경 소스 및 사용 패키지, ROM/state/integration을 검사하며 strict state_dict 로드를 사용한다. 평가는 소스 전체 동일성을 요구하는 resume와 달리 정책/환경 계산 관련 소스를 검사한다. evaluator의 소스 해시는 평가 protocol에 포함되므로 평가 구현 변경을 같은 protocol로 조용히 취급하지 않는다. 구형 Run의 자동 snapshot migration은 없다.

## 평가 protocol과 독립성

protocol은 게임/고정 state·ROM/integration·관측 크기/색상/stack·action repeat·보상/종료 규칙·전처리·행동 목록·seed 목록·횟수·행동 선택 방식·영상 길이·평가 코드 해시를 포함한다. canonical JSON SHA-256이 protocol ID다. 평가 게임의 최대 프레임은 protocol 제한과 원래 GameConfig 제한 중 작은 값이다. protocol 원본과 결과가 Run 안에 독립 artifact로 남는다. 서로 다른 protocol ID의 결과는 CLI 비교에서 거부한다.

확률적 평가에서는 episode별 seed로 생성한 **로컬 CPU torch.Generator**와 CPU 확률의 `torch.multinomial`로 행동을 선택한다. 추론 장치와 샘플러 장치를 구분한다. 결정론적 관전은 argmax이며 동률은 가장 작은 행동 ID를 고른다. seed 하나의 대표 에피소드만 허용하고 seed 변경을 NES 플레이 다양성으로 설명하지 않는다.

실제 학습용 ConnectomePolicy를 `eval()`·gradient 비활성화·inference_mode로 실행한다. 평가에는 optimizer가 없고 현재 정책은 전역 관측/보상 정규화 통계가 없다(픽셀 /255 고정 변환). 별도 프로세스·환경·RNG를 사용하므로 학습 RNG/모델/optimizer/카운터에 접근해 쓰지 않는다. 평가 결과만 `evaluations/<ID>/`, protocol만 `protocols/<hash>.json`에 추가한다. 동일 snapshot의 반복 평가도 새 ID를 사용한다.

## 지표, 영상, 운영

episode별 최대 진행 거리(pixels), 원래 단위 보상 합, 전이/실제 emulator frame 수, terminated/truncated 및 종료 사유를 기록한다. 거리 전체 목록·평균/중앙값/최소/최대, 완료 횟수와 전체 평가 횟수·비율, 사망/무진행/시간 제한 등 종료 사유 집계를 제공한다. 게임 계약 위반이나 비유한 보상은 성공 평가로 집계하지 않는다.

영상은 첫 episode의 처음 N초만 녹화한다(1~60초, 기본 15초). 다른 seed의 장면을 한 영상에 이어붙이지 않는다. 기존 VP9/CRF45/12fps/무음 압축 경로를 공유하며 mode·Run·평가·snapshot·모델 해시·protocol·episode/seed를 metadata에 연결한다. 평가 녹화가 실패하면 결과도 실패로 표시하고 비교에서 제외한다. 브라우저는 평가/관전/학습 기록을 구별하고 선택한 영상의 snapshot/protocol을 표시한다.

환경 1개에서 평가 episode를 순차 실행한다. 기본 CPU이고 CUDA는 명시 옵션이다. 여유가 없으면 학습을 안전 저장·종료한 후 평가하고 resume하는 절차를 사용한다. 평가 자체는 기존 trainer를 중단하지 않는다. 초기 평가는 부모 trainer가 첫 rollout 전에 기다리는 순차 경로다. `--realtime`은 결정론적 관전의 약 60 emulator fps pacing이며, 실시간 화면 스트리밍은 아니다. 완성 영상은 브라우저 native controls로 정상 게임 속도에 재생한다.

평가의 wall time·프로세스 peak RSS·인코더 peak RSS·PyTorch peak CUDA allocated를 보고한다. 이는 GPU 전체 VRAM이나 동시 부모/자식 합산 RSS가 아니다. 환경 close와 ffmpeg wait/kill을 거쳐 worker를 정리한다.

## 검증 범위

합성 환경도 실제 정책과 CLI 프로세스를 사용한다. snapshot의 초기/후속 연결, optimizer/resume 파일 없이 평가, 평가 전후 학습 artifact 해시 불변, 초기 평가 on/off의 다음 학습 갱신·Torch RNG 일치, 같은 확률적 protocol의 trace 재현, 결정론적 대표 관전, 보상/거리/프레임 단위, 영상 길이 상한, protocol 차이/변조·snapshot 변조 거부를 검사한다. realtime 평가 후 인코더 PID 소멸도 외부에서 확인한다. 브라우저에서는 실제 HTTP 서비스에서 평가 영상을 선택·재생하고 snapshot/protocol을 확인한다.

실제 NES 결과는 fixture와 구분해 별도 `t05-evidence.json`에 기록한다. 이것은 AC-10/AC-11의 기반이며 작은 표본의 성과 개선이나 통계적 일반화를 입증하지 않는다. 장기 자원 예산·최고본 보존 정책·회로 활동 동기 재생은 후속 범위다.

## 실제 NES 증거

최종 검증은 A2의 실제 FlyWire 부분 그래프(4,622개 뉴런, 8,010개 연결)와 등록된 NES ROM/state를 사용한다. `configs/evaluation-small.json`을 축소한 seed [11,22,33], episode 최대 600 frame, 첫 episode 영상 5초 조건으로 초기/후속을 비교한다. 학습은 RTX 5090에서 8 rollout × 32 transition, 평가는 별도 CPU 프로세스에서 실행한다. 결정론적 관전은 seed11·180frame·3초 영상·realtime으로 별도 실행한다.

초기 평가 완료 시각이 첫 학습 시작보다 이른지 확인하고, 후속 평가·관전 전후 Run의 학습 artifact SHA-256 전체가 동일한지 확인한다. 비교 결과와 식별자·환경/종료·자원 정보는 `t05-evidence.json`에 보존한다. Run 원본에는 모든 trace·snapshot·영상이 있다.

2026-10-10 최종 코드의 `reports/t05-nes-5090-003/`에서 확인했다. 초기 거리 [682,554,250], 후속 거리 [556,555,255] pixels, 양쪽 완료 0/3이다. 초기/후속 평가 wall time은 각각 약 1.55/1.52초이며 영상은 21,565/20,872 bytes(각 5초)다. 별도 결정론적 관전 영상은 13,675 bytes(3초)다. 짧은 실행에서 성능 개선은 입증되지 않았다. [검증 증거](t05-evidence.json)에 Run manifest·snapshot metadata·평가 protocol과 각 결과를 함께 남겼다.
