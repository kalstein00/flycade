# A2 / AC-02: 고정 FlyWire 실제 부분 그래프

2026-10-10, Ubuntu/WSL2, Python 3.12.9에서 확인했다. #3의 데이터 준비 결과이며 실제 정책·게임 학습의 완료를 뜻하지 않는다. 원시 증거 요약은 [a2-evidence.json](a2-evidence.json), 출처·SHA-256은 [고정 원본 명세](../../src/flycade/data/flywire-v783.json), 실행 안내는 [graph-preparation.md](../graph-preparation.md)에 있다.

## 실행

```bash
uv sync --locked --extra graph
uv run --locked --extra graph flycade fetch-graph-data
uv run --offline --locked --extra graph flycade prepare-graph --config configs/graph-visual.json --output .flycade/graphs/visual-a2-final-001
uv run --offline --locked --extra graph flycade prepare-graph --config configs/graph-visual.json --output .flycade/graphs/visual-a2-final-002
uv run --offline --locked --extra graph flycade inspect-graph .flycade/graphs/visual-a2-final-001 --cache .flycade/data/v783
uv run --offline --locked --extra graph flycade fetch-graph-data
```

최초 파일 취득은 공식 HTTPS URL에서 수행했다. 연결 파일은 다운로드 중 실행 환경이 재시작되어 HTTP Range로 남은 바이트를 받아 결합했고 전체 MD5를 archive 게시값과 대조했다. 이후 공개 CLI의 fetch로 세 파일의 캐시 재사용과 SHA-256 검증을 확인했다. 일반 CLI 다운로드는 임시 파일에서 검증 후 게시하며 중단 지점 재개 기능은 제공하지 않는다. 작은 fixture에서는 실제 다운로드·캐시 재사용 경로를 CLI로 실행한다.

준비와 재구성은 위 공개 CLI를 사용한 별도 프로세스다. 두 출력의 계산용 그래프 해시와 측정 파일을 제외한 모든 artifact 해시가 일치했다. `--offline`은 uv의 패키지 접근을 차단하며, prepare/inspect 구현 자체에 네트워크 호출이 없다. 재사용한 fetch는 원본 접속 없이 캐시 해시만 확인한다.

유형 선택은 L1(1,579), Mi1(1,580), T4a(1,463)다. 실제 뉴런을 그대로 보존한 유도 부분 그래프이며 축약·합성 edge 추가는 없다. 원본 영역 간 합산 뒤 방향 뉴런 쌍 임계값을 적용했다. 고립되거나 입출력 경로에 참여하지 않는 선택 뉴런도 명시적으로 남긴다. 따라서 이 그래프를 사용하는 후속 정책은 경로 미참여 뉴런과 readout 설계를 고려해야 한다. 이 규모는 최초 데이터 실험의 결과이며 최종 학습 프리셋 확정은 아니다.

L1 입력 1,579개 중 **1,532개(97.0234%)**가 지정 출력 중 하나 이상에 도달한다. T4a 출력 1,463개 중 **1,456개(99.5215%)**에 지정 입력에서 도달할 수 있다. 도달하지 못한 입력은 47개, 출력은 7개다. 방향성 경로 예시는 다음과 같다(원본 ID 문자열).

```text
720575940620354008 → 720575940605262880 → 720575940599755718
```

## 재현성과 자원

계산용 그래프 SHA-256:

```text
97ea609f3c64c24ebfd90c73b4590878d437b5e67851dff1f60f9e74c730de7f
```

| 별도 CLI 프로세스 | 전처리 시간 | peak RSS |
| --- | ---: | ---: |
| 첫 실행 | 6.849초 | 2,187,984,896 bytes (약 2.04GiB) |
| 캐시 재구성 | 6.334초 | 2,215,907,328 bytes (약 2.06GiB) |

전처리는 원본 해시 검증부터 그래프와 보고서 생성까지 측정하며 다운로드 시간은 제외한다. RSS는 Linux 프로세스 수명 중 최고값이고 Arrow·Python·파일 매핑 비용을 포함한다. DuckDB 512MB 예산이 전체 프로세스 RSS 상한이라는 뜻은 아니다. 동시 실행 부하와 파일 캐시에 따라 시간·RSS가 달라진다. 32GB Windows 전체 RAM이 아니라 현재 WSL 환경에서의 측정이다. GPU/VRAM·모델 역전파·학습 처리량은 측정하지 않았다.

원본 ID는 JSON에서 문자열이고 내부 인덱스는 숫자다. 그래프·설정·출처 해시는 manifest로 기록하며 구현 파일 SHA-256과 패키지 버전도 보고한다. 실제 원본 파일과 두 그래프 디렉터리는 git 제외된 `.flycade/` 캐시에 남긴다. 원본이 없더라도 완성된 artifact만으로 inspect할 수 있으며, 재구성에는 원본 캐시가 필요하다.

## 자동 검증과 판정

부모 #1에서 합의한 CLI 프로세스와 공개 artifact 경계에서 검증했다. 브라우저 기능은 이 데이터 준비 티켓에 없다.

- 작은 fixture: 영역 간 합산 **후** 임계값, 역방향 구별, 큰 ID 보존, self-loop drop/keep, 도달 비율과 경로, 연결되지 않은 선택 거부.
- 재구성: 두 프로세스의 동일 artifact, 원본 행 순서를 바꿔도 동일한 계산용 그래프 해시.
- 캐시와 실패: 다운로드 후 원본을 제거한 상태의 캐시 재사용, 원본·출력의 누락/손상, 기존 출력 보호, 숫자 ID 거부.
- 타입 검사: `uv run --extra graph mypy src` 통과.
- 개별 테스트: `uv run --extra graph pytest tests/test_graph_cli.py` — 7개 통과.
- 전체 테스트: `uv run --locked --extra graph pytest -q` — **15개 통과, 3개 건너뜀**, 5.51초. 건너뛴 3개는 `FLYCADE_TEST_ROM` 미지정으로 실행하지 않은 기존 실제 NES 검사다. 그래프 검사 7개는 모두 실행했다.
- 배포: `uv build --wheel` 성공, wheel 내부의 고정 원본 JSON 포함 확인.
- 병렬 코드 리뷰: Standards의 해시 계산 중복 1건을 공통 함수로 정리하고 재검토 통과. Spec 지적 0건. 남은 지적 없음.

A2/AC-02의 실제 고정 원본 재현은 위 해시·통계·ID 대응·재실행으로 확인했다. 연결 경로 확인은 정책 구현의 입력 자료이며 AC-03의 실제 행동 계산 경로 검증을 대신하지 않는다. 생물학적 부호·감각 운동계 재현·학습 성과·AC-12의 1시간 운영은 이번 결과의 범위 밖이다.
