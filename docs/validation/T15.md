# T15 보존 정책과 오프라인 운영

Run 디렉터리는 WSL의 Linux 파일시스템(예: `~/vscode/flycade/reports/my-run`)에 둔다. Windows 탐색기에서는 `\\wsl.localhost\<배포판>\home\<사용자>\vscode\flycade\reports`로 접근한다. 실행 중 파일을 탐색기에서 이동하거나 수정하지 않는다. 브라우저는 WSL에서 실행한 `flycade live`가 출력한 localhost 주소로 접속한다.

```bash
uv run --offline --locked --extra graph --extra train flycade storage reports/my-run
uv run --offline --locked --extra graph --extra train flycade storage reports/my-run \
  --keep-evaluations 3 --keep-videos 10 --log-bytes 8388608 --apply
uv run --offline --locked --extra graph --extra train flycade checkpoints reports/my-run
uv run --offline --locked --extra graph --extra train flycade pin-checkpoint reports/my-run <checkpoint-id>
```

`storage`는 남은 공간, 보존 설정, 마지막 정리 결과·오류와 마지막 정상 저장 시점을 보여 준다. 옵션 없는 명령은 읽기 전용이다. 설정 변경과 `--apply`는 학습이 중지된 Run에서 수행한다. GUI의 **저장 공간**을 펼치면 같은 정보가 보인다. 64MiB 미만의 여유 공간은 공간 부족으로 표시한다. 이 기준은 다음 저장 크기를 보장하는 예약 공간이 아니다.

기본 최근 정상 checkpoint3개와 protocol별 최고1개·최신본·수동 pin을 보호한다. 초기 정책, 각 protocol의 초기·최고·최신 평가 영상·관찰 이력과 수동 pin된 snapshot의 평가 기록도 보호한다. 같은 초기본을 반복 평가해도 첫 초기·최고·최신 및 최근 한도를 넘는 중복 기록까지 영구 보존하지 않는다. 각 protocol의 최근 평가3개는 추가로 유지한다. 평가별 영상·관측·전이 로그·보고서는 하나의 디렉터리로 정리된다. 먼저 평가 목록에서 제외하고 디렉터리 전체를 Run 안의 임시 정리 영역으로 옮긴다. 중간 실패 시 보호본은 손대지 않으며 재실행 때 남은 보고서에서 목록을 재구축하고 미삭제 디렉터리·목록 없는 영상을 다시 정리한다. 실패·중단된 평가도 protocol별 최근 설정 개수만 유지하며 살아 있는 평가 lease와 수동 pin은 보호한다.

학습 영상은 최근10개(각 최대 게임시간60초)를 유지하는 순환 기록이다. 오래된 모든 학습 영상을 영구 보관하지 않는다. 특정 정책의 영상을 보존하려면 해당 checkpoint를 pin하고 고정 평가를 기록한다. 학습·갱신·저장 이벤트 로그는 각각 기본8MiB 한도에서 최근 완전한 JSON 행을 유지한다. 누적 진도는 로그가 아니라 full-state checkpoint에 있다. 한도 초과 시 오래된 원시 전이 로그는 사라지므로 장기 연구용 원자료가 필요하면 정지 후 Run을 별도 백업한다.

정리는 저장 경계·세션 종료 및 단독 고정 평가 완료 후 수행한다. 실행 중 평가의 lease가 보호하는 snapshot은 삭제하지 않는다. 그래프, 초기 가중치, branch의 `origin/`과 외부 Run은 정리하지 않는다. branch는 원본 checkpoint와 그래프를 독립 복사하므로 부모 정리로 재개 가능성이 사라지지 않는다. 보호 항목의 용량은 자동 삭제로 제한하지 않는다. 많은 수동 pin·protocol·분기를 만들면 공간이 계속 필요하다.

정리 실패는 `storage-status.json`과 CLI/GUI에 남으며, 저장 실패는 기존 저장 상태·마지막 복구 시점에 표시한다. 공간 부족 시 먼저 학습 저장 상태를 확인하고 공간을 확보한다. 초기·best·pin·graph를 직접 삭제하지 않는다. 정리 실패 원인이 권한 문제이면 Run 디렉터리의 쓰기 권한을 복원한 뒤 `storage --apply`를 다시 실행한다. 파일이 누락되면 일치하는 로컬 백업을 복원한다. 최신 온라인 데이터로 자동 대체하지 않는다.

## 오프라인 전제

최초 설치 때 Python 환경과 패키지, ffmpeg, ROM 등록, 고정 그래프 준비가 완료되어 있어야 한다. 이후 새 프로세스의 `resume`, `evaluate`, `live`, `history`, `storage`는 로컬 artifact만 사용한다. `uv run --offline --locked`로 패키지 다운로드도 금지할 수 있다. 애플리케이션은 학습 재개 중 누락 파일을 다운로드하지 않는다. 체크포인트의 코드·패키지·ROM·graph 식별자가 다르면 명시적으로 거부하며, 원래 버전과 백업을 복원해야 한다.

## 검증

CLI/artifact 경계에서 순환 정리, initial/best/latest/pin 보호, 분기 독립성, 원본 그래프 유지, 고아 partial 정리, 삭제 권한 오류와 마지막 정상본 유지, 오프라인 새 프로세스 재개·평가 및 누락 그래프 거부를 검사한다. 오프라인 검사는 테스트용 POSIX connect 경계에서 loopback 외 연결을 ENETUNREACH로 차단하고 실제 차단 probe를 확인한다. 브라우저는 정리 후 보호본 비교·영상/관측 재생 및 삭제된 평가의 데이터 없음 표시를 확인한다. 실제 Windows 화면 확인은 T16 사용자 인수에서 별도로 수행한다.

대상 검증: 신규 CLI·브라우저5개 통과(59.38초), 기존 복구 검사 포함17개 통과(141.44초), mypy35개 소스 통과. 실제 NES·RTX5090 Run `reports/t15-storage-002/run`은 외부 connect를 차단한 상태에서1 update 저장 후 새 프로세스로6 updates까지 재개했다. 초기·pin·최고·최신 기준으로 평가4개가 남았으며 보호된 초기 영상과 실제 회로 이력을 재생했다. [실제 근거](T15-evidence.json), 화면은 `t15-screens/`에 있다.

명세 리뷰의 정리 재시도·실패 평가 보존 한도 지적은 추가 CLI 회귀 검사로 재현 후 수정했다(12.39초 통과). UI 리뷰는 ship, 문서 검토는 기존 시스템 유지로 변경 없음이다. detector의 기존 template img 경고2건은 실제 픽셀을 런타임에 채우는 구조로 화면에서 확인했다.

## Standards

문서화된 규칙 위반0건, 정책 검증 중복 휴리스틱1건. 읽기·쓰기 경로가 같은 검증 함수를 쓰도록 수정했다.

## Spec

정리 재시도 누락(P1)과 비완료 평가 무제한 보존(P2)2건을 수정하고 명세 재리뷰에서 해결을 확인했다. 두 축 모두 남은 지적은 없다.

전체 회귀103개를 파일별3개 독립 프로세스로 실행했다.101개가 통과했고,2개는 새 storage 상태/정책 파일을 학습 상태 불변 대상으로 취급하던 기존 검사였다. 해당 관리 메타데이터만 제외하고 모델·optimizer·RNG·checkpoint·Run 설정 등 기존31개 동일 파일 검증은 유지했다. 평가 CLI 파일 전체6개 재검사가 통과했다(43.40초). 최종 변경에 대해103개 고유 검사의 통과를 확인했다.
